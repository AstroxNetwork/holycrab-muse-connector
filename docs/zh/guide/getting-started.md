# 你在做什么

Muse 是 Meta 的个人 AI agent，通过 **connector** 接入第三方服务。

最重要、也最让人意外的一点是：**没有应用要注册，也没有 app id 要申请。**
Meta 不会运行你的代码。你暴露一个 HTTP API，Muse 读取它的描述，然后代表用户调用它。

## 两个文件决定一切

Muse 从你的服务读取一份 OpenAPI 文档和一个 `llms.txt`，然后调用你的 API。

| 文件 | 谁读 | 作用 |
|---|---|---|
| `/openapi.json` | 平台 | 机器可读：有哪些操作、要什么参数、返回什么 |
| `/llms.txt` | 模型 | 同样内容的文字版，外加行为规则 —— 什么时候先问用户、慢任务怎么等 |

这就是全部的接入面。没有 SDK 要装，也没有回调要实现。

```text
Muse ──(connector 令牌)──▶ 你的 connector ──(你的凭证)──▶ 你的 API
        可撤销、按连接限定      这个模板          只存在服务端
```

## 模板替你解决了什么

Muse 是从 Meta 的基础设施调用你的 API，代表的是一个**并不在旁边盯着**的人。由此产生三件事，
也正是这个模板存在的理由：

1. **模型不能持有你的 API key。** 用户拿到的是一个只指向某一条连接的令牌。可撤销、范围受限、
   不含任何上游密钥。你真正的凭证留在服务端。
2. **慢且花钱的操作靠的是措辞，不只是代码。** 如果模型为了"查进度"重试了一次 `POST`，
   用户就会被扣两次。见[异步与付费](/zh/guide/async-and-paid)。
3. **描述就是接口。** 模型根据你写的文字决定要不要调用。
   `"读取你的余额"` 不如 `"只读。此调用无法转移资金。"`

## 你能得到什么

产物是一个普通的、带认证的 OpenAPI 服务。Muse 会读它 —— 但任何懂 OpenAPI 的东西都能读：
ChatGPT、Claude、Cursor、你自己的 agent。

::: tip 没有锁定
除了 `llms.txt` 里的一些表述习惯，这里没有任何东西是 Muse 专属的，而那些你都可以改。
不需要在我们这里注册账号、拿 key，也没有遥测。部署到哪都行，不想要的部分直接删。
:::
