一个下午做好你的 Muse connector

Muse 是 Meta 的个人 AI agent，通过 connector 接入第三方服务。 没有应用要注册，也没有 app id 要申请 —— 你只要暴露一个 HTTP API，让 Muse 能读取它的描述并调用。这份文档带你从空仓库走到 Muse 能用的 connector。

开始快速上手 查看源码

你在做什么

两个文件决定 Muse 能不能用你的服务：一份 OpenAPI 文档和一个 llms.txt。Muse 读这两样，然后代表用户调用你的 API。

/openapi.json

给机器读：有哪些操作、要什么参数、返回什么。Muse 靠它学习你的 API。

/llms.txt

同样内容的文字版，外加行为规则 —— 什么时候必须先问用户，慢任务怎么等。

按连接的令牌

用户拿到的是限定范围的令牌，不是你的 API key。可撤销，模型也看不到真实凭证。

Muse ──(connector 令牌)──▶ 你的 connector ──(你的凭证)──▶ 你的 API
        可撤销、按连接限定      这个模板          只存在服务端

产物就是一个普通的 OpenAPI 服务。Muse 会读它，但任何懂 OpenAPI 的东西都能读 —— ChatGPT、Claude、Cursor、你自己的 agent。除了 llms.txt 里的一些表述习惯，这里没有任何东西是 Muse 专属的，而那些你都可以改。

快速开始

五分钟跑起来。需要 Node 20+。

  1. 克隆并安装 
    git clone https://github.com/AstroxNetwork/muse-connector-template.git my-connector
cd my-connector
npm install
  2. 设置三个变量

    PUBLIC_URL 和 DASHBOARD_URL 故意没有默认值 —— 原因见常见坑。

    cp .env.example .env

CONNECTOR_SECRET=$(openssl rand -base64 48)   # 32 位以上
PUBLIC_URL=http://localhost:8787              # 本地允许 http
DASHBOARD_URL=https://example.com             # 必须是 https
LINK_SECRET=dev-link-secret
  3. 启动 
    export $(grep -v '^#' .env | xargs)
npm run dev

    它会打印一条关于缺 KV 的警告。本地开发这是正常的。

  4. 看看 Muse 会读到什么 
    curl -s localhost:8787/openapi.json | jq '.paths | keys'
# [ "/v1/me", "/v1/things", "/v1/jobs", "/v1/jobs/{id}" ]

curl -s localhost:8787/llms.txt

    这四个 operation 都是占位的。仔细读一下 llms.txt 的输出 —— 你写进 operation 的每一个字都会出现在里面。

  5. 签发令牌并调用 
    TOKEN=$(curl -s -X POST localhost:8787/v1/link \
  -H 'content-type: application/json' \
  -H 'x-link-secret: dev-link-secret' \
  -d '{"subject":"you@example.com"}' | jq -r .token)

curl -s localhost:8787/v1/me -H "Authorization: Bearer $TOKEN" | jq

跑一下测试。测试本身就是规格说明，其中最重要的一条是： 已付费操作被重试时，不能创建第二个任务。

npm test        # 50 个测试
npm run typecheck

改成你自己的

只需要改三处，其余都是管道。

1. 声明你的能力

打开 src/operations.registry.ts。删掉三个 demo* operation，然后每个能力加一个 Operation。 这一条定义会同时生成路由、OpenAPI 路径、llms.txt 里的一行，以及助手的行为规则。

{
  id: "createVideo",              // 保持稳定；模型可能会引用它
  method: "post",
  path: "/v1/videos",
  summary: "根据提示词生成视频",
  description: "启动一次生成，返回一个需要跟踪的任务。",
  input: { schema: z.object({ prompt: z.string().min(1).max(4000) }) },
  spends: { kind: "credits", note: "消耗 1 个生成积分。" },
  async: { pollWith: "getVideo", typicalSeconds: 90 },
  handler: ({ provider, connection, body, idempotencyKey }) =>
    provider.createVideo(connection, body as any, idempotencyKey),
}

其中两个字段承担了主要工作。spends 让描述明确告诉模型这要花钱； async 告诉它去轮询哪个操作，而不是重复提交。两者都在下面详述。

2. 实现你的服务

在 src/providers/ 里对接你的真实 API，做完后删掉 placeholder.ts。接口一开始故意做得很小：

export interface ProviderPort {
  whoami(connection: ConnectionRecord): Promise<WhoAmI>;
  // 上面每声明一个 operation，这里就加一个方法
}

抛出 UpstreamError 就能控制调用方看到的 HTTP 状态码 —— 这是 connector 其余部分唯一依赖的约定：

throw new UpstreamError(`no such job: ${id}`, 404);

3. 命名

SERVICE_NAME 控制 OpenAPI 标题、/health 和 llms.txt。包名和仓库名随你改。

异步与付费

这是 connector 最容易出错的地方，而且几乎从来不是代码问题 —— 是措辞问题。 生成是异步的，而且花用户的钱。如果模型为了"查进度"重试了一次 POST，用户就会被扣两次钱。

重复扣费的失败模式。慢操作 + 急切的模型 = 重复扣费。 有三道防线，而且三道都要有。

防线位置
标 spends，让描述写明要花钱你的 operation
标 async + pollWith，让模型去轮询而不是重提你的 operation
支持 Idempotency-Key，让重试返回同一个任务你的 provider

只声明一次，它们就会传播到两份文档里：

spends: { kind: "credits", note: "消耗 1 个生成积分。" },
async: { pollWith: "getVideo", typicalSeconds: 90 },

OpenAPI 会多出 x-long-running、x-poll-operationId 和 x-requires-confirmation，生成的描述会变成：

COSTS THE PERSON: Costs 1 generation credit. Do not call this until they
have agreed to this specific request. This returns immediately with a job to
track — poll `getVideo` (typically ready in about 90s). Do not resubmit to
"check" progress; that would create a second job.

而 /llms.txt 会长出一段模型每次都会读到的内容：

## Waiting on work
- `createVideo` returns a job; poll `getVideo` (about 90s).

Polling is free and safe. **Re-submitting is not** — it starts a second job.
A timeout is not a failure: keep polling the same job.

说清楚这个调用"不会"做什么

描述是给正在决定要不要动手的模型读的。"读取你的余额" 不如 "只读。此调用无法转移资金。" 把边界写出来 —— 正是它阻止模型承诺你做不到的事。

部署

同一份源码，三种目标。核心代码里没有任何平台相关逻辑。

Vercel

npm i -g vercel
vercel link
vercel env add CONNECTOR_SECRET
vercel env add PUBLIC_URL        # https://muse.your-domain.com
vercel env add DASHBOARD_URL     # https://your-domain.com
vercel env add KV_REST_API_URL   # Vercel KV 或 Upstash
vercel env add KV_REST_API_TOKEN
vercel deploy --prod

vercel.json 会把所有路径重写到 api/index.ts， 这样对外 URL 保持在根路径。Muse 必须看到 https://muse.your-domain.com/openapi.json，而不是 /api/openapi.json。

Cloudflare Workers

npm i -g wrangler
wrangler kv namespace create MUSE_KV   # 然后取消 wrangler.jsonc 里 kv_namespaces 的注释
wrangler secret put CONNECTOR_SECRET
npm run deploy:cf

wrangler.jsonc 开了 nodejs_compat， 因为签名令牌用了 node:crypto。不开这个标志 Worker 无法打包。

Docker / 任何主机

docker build -t muse-connector .
docker run -p 8787:8787 \
  -e CONNECTOR_SECRET=... \
  -e PUBLIC_URL=https://muse.your-domain.com \
  -e DASHBOARD_URL=https://your-domain.com \
  muse-connector

持久化 —— 有真实用户前必做

没有存储时，连接信息存在内存里。本地没问题，serverless 上不行： 每个请求可能落在新的 isolate 上，于是用户会莫名其妙被登出；更糟的是， 撤销授权只对某一个 isolate 生效。 缺少绑定时服务会打印警告，这是故意的。

存储怎么做
Cloudflare KV绑定 MUSE_KV
Vercel KV / Upstash设置 KV_REST_API_URL + KV_REST_API_TOKEN
其他任意方案实现只有四个方法的 ConnectionStore 接口

切换是自动的：配了 KV 就会用它。

怎么被找到

这是两件不同的事，区别很重要。

Custom Connector目录收录
方式用户把 Muse 指向你的 URL 并提供令牌在 muse.ai/platform 提单
审核不审核 —— Meta 官方明确说明功能 + 安全 + 法务 + 端到端测试
分发无；用户必须知道你的 URL进目录，可被选入精选位
速度当天可用未知；Meta 未公布 SLA

先走 Custom Connector。它不需要 Meta 做任何事， 所以你可以先验证 Muse 能不能理解你的异步模型，再去投入提交。 准备清单在 connector/SUBMISSION.md。

规划之前值得知道的是：针对目录收录，Meta 至今没有公布分成比例、费用和审核时长； 而且 connector 条款只有在登录后才看得到。

常见坑

为什么 PUBLIC_URL 和 DASHBOARD_URL 是必填的？

它们不是装饰。PUBLIC_URL 会写进 OpenAPI 的 servers —— 也就是 Muse 被指向去调用的地址； DASHBOARD_URL 会打印给用户，作为撤销授权的地方。 有默认值就意味着：一个没配全的部署会告诉 Muse 去调用错误的地址，并把用户送到错误的站点。 所以 connector 选择直接拒绝启动。

必须用子域名吗？

不必。任何公网 HTTPS 地址都行 —— 子域名、主域名下的路径，或者测试时用 *.workers.dev。子域名是个好习惯，因为你的主站很可能已经占用了 /llms.txt 和 /openapi.json，而且它的 WAF 可能把 API 流量当成机器人流量处理。

这需要 MCP 吗？

不需要。Muse 的 custom connector 走的是普通 REST 加一份 OpenAPI 文档。 MCP 是另一套协议，也是另一个产品（命令行工具 Muse Code）。

如果模型在错误的时机调用了怎么办？

每个调用都会经过 Meta 的权限层，它可以放行、拒绝，或者询问用户。 你要做的是让请求可读：清晰的 summary、诚实的 description，以及花钱时的 spends 说明。

不用 Muse 也能用吗？

能。它就是一个带令牌签发端点的、经过认证的 OpenAPI 服务。把任何 agent 指向它都行。

真的是 Apache-2.0 吗？

是。随便 fork、改名、去掉品牌。你重新分发的那部分文件保留 NOTICE 就行；你部署的服务不需要标注来源。
